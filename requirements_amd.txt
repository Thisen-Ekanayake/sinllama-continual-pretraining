# requirements_amd.txt
# ROCm / AMD MI300X stack for training and pod-side eval (sft/, gen/,
# wikipedia_sft/, weights_analysis/). requirements.txt is a CUDA-flavored
# environment instead -- torch==2.10.0 there pulls in nvidia-*-cu12 wheels,
# which do not apply to an AMD GPU at all.
#
# This file is requirements.txt with exactly the corrections recorded in the
# "MI300X training throughput" memory note (measured 2026-08-15, UltraChat
# SFT smoke run, LoRA r64, B=8 x accum 8, seq 2048):
#
#   | stack                          | s/step | peak VRAM        |
#   |---------------------------------|--------|------------------|
#   | torch 2.5.1+rocm6.2             | 13.5   | --               |
#   | torch 2.11.0+rocm7.13           | 7.90   | 176 GiB (96%)    |
#   | + liger-kernel fused_linear_CE  | 7.90   | 131 GiB (72%)    |
#
# On the old stack, sdpa silently ran the O(L^2) math kernel (48 ms/layer vs
# 7 ms at B=8 S=2048) and the 139,336-wide lm_head GEMM ran at 53 TFLOPS
# instead of 607 -- newer hipBLASLt tiles that width correctly, torch 2.5.1's
# did not. Liger's fused_linear_cross_entropy never materializes the
# B x seq x 139,336 logits tensor, for free (same step time, same loss to 4
# decimals). See sft/config.yaml's header for the same numbers in context.
#
# Diff from requirements.txt:
#   - torch 2.10.0 -> 2.11.0, torchvision paired to 0.26.0 (bump to the fast,
#     measured-good pair; see install note below)
#   - removed all nvidia-*-cu12 / cuda-bindings / cuda-pathfinder packages
#     (CUDA-only; meaningless on an AMD GPU, and pip would otherwise still
#     resolve a CUDA torch wheel underneath them)
#   - removed bitsandbytes: every config.yaml in this repo trains bf16 LoRA
#     with no quantization -- "4/8-bit is unreliable on ROCm, unnecessary at
#     192 GB" (sft/config.yaml). Kept out even though benchmark/mrlbenchmarks
#     supports an optional --quant flag; that flag is for CUDA eval boxes.
#   - removed unsloth, unsloth_zoo, xformers, cut-cross-entropy: not imported
#     anywhere in sft/, gen/, wikipedia_sft/, benchmark/, mmlu/, hellaswag/,
#     cpt/ or inference/ (verified by grep) -- this pipeline trains with plain
#     transformers + peft + Trainer, not the unsloth fast-kernel stack, and
#     that stack is CUDA-only / unofficial on ROCm anyway.
#   - added liger-kernel==0.5.10, pinned: every stage's config.yaml sets
#     use_liger_kernel: true, and 0.6.0+ hard-requires transformers >= 4.52,
#     which conflicts with the 4.51.3 pin below.
#
# Install order matters: torch/torchvision must come from AMD's ROCm wheel
# index, not plain PyPI -- `pip install -r` alone resolves a CUDA build and
# fails at runtime with "Found no NVIDIA driver on your system" the moment
# transformers touches torch.cuda.mem_get_info, even though the box is an AMD
# GPU throughout (ROCm's HIP backend is exposed under the torch.cuda.*
# namespace for compatibility, so that call is normal -- the CUDA-only build
# underneath it is the actual bug). Confirmed working index: PyTorch publishes
# ROCm wheels under the "rocm6.2" folder name even though it runs against this
# pod's ROCm 7.x userspace (rocm-7-14-... hostname) -- the wheel is "the ROCm
# 6.2 build, compatible with ROCm 7.0", not a mismatch.
#   pip install torch==2.11.0 torchvision==0.26.0 torchaudio \
#       --index-url https://download.pytorch.org/whl/rocm6.2
#   pip install -r requirements_amd.txt
# If a fresh pod's ROCm index ever moves past 6.2, swap the folder name only
# -- the rest of this file is unaffected.
